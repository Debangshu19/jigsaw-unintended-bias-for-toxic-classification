START HERE · WHAT WE BUILT

What this project is

Raven is a system that detects toxic and hate-speech comments. It answers one question: which comments need a human moderator to look at? Instead of a person reading every comment, Raven flags the risky ones as "needs review" and lets the safe ones through. The point is to save the moderator's time, not to replace their judgement.

What we built

One model, one API, and three clients. The three clients all speak the same API contract.

The model

A fine-tuned DistilBERT classifier that outputs P(toxic) for a comment. measured by us

The API

A FastAPI service (raven-api). It has a fallback chain (real model → LLM via gateway → keyword heuristic) so a demo never hard-crashes.

Web client

A React website (raven-web) with a live demo you can type into.

Browser extension

A Chrome Manifest-V3 extension (extension) that flags comments inline on X, YouTube and Instagram.

Mobile client

An Expo mobile shell (raven-mobile) that calls the same API.

FOUNDATIONS · DATA & METRICS

Data and how we measure

The English track uses the Jigsaw "Unintended Bias in Toxicity Classification" data (the Civil Comments corpus). It has 1,804,871 comments measured by us. Each comment carries a continuous target in [0,1]. We treat a comment as toxic when target ≥ 0.5, so the score is binarised at 0.5. The data also has identity columns (muslim, black, white, female, and others) that let us measure bias by group.

Why balancing and the right metric matter

The raw data is heavily imbalanced: 1,660,537 non-toxic against 144,334 toxic comments measured by us. That is about 11.5 : 1, roughly 8% toxic. On data like this, plain accuracy is misleading. A model that labels everything "non-toxic" already scores about 92% accuracy while catching no toxic comment at all. So we cannot trust accuracy alone; we have to look at how the minority (toxic) class is handled.

The metrics, one line each

MetricPlain definition
AccuracyFraction of all comments labelled correctly.
Precision (toxic)Of the comments we flagged toxic, how many really were.
Recall (toxic)Of the truly toxic comments, how many we caught.
F1 (toxic)Harmonic mean of precision and recall — one number that balances both.
Macro-F1F1 computed per class, then averaged — treats both classes equally regardless of size.
ROC-AUCProbability the model ranks a random toxic comment above a random non-toxic one.
Jigsaw bias-aware AUCA weighted blend of the overall AUC and per-identity-subgroup AUCs, so a model is rewarded only if it ranks well within each identity group, not just on average.

Two evaluation regimes — kept separate on purpose

The numbers in this project come from two different setups. We keep them apart because mixing them would be a mistake.

Regime A — RNN / classical family

  • Trained and evaluated on the large, imbalanced split.
  • Reported with the Jigsaw bias-aware AUC.
  • Keras tokenizer, vocab 100,000, max_sequence_length 300.
  • Pretrained 300-d word embeddings, shape (276,289 × 300).

Regime B — DistilBERT

  • Trained on a balanced down-sample: 50,000 per class = 100,000.
  • Split 80/20 → 80,000 train / 20,000 val (10k per class).
  • Reported with plain accuracy / F1 / ROC-AUC on that balanced val set.
  • WordPiece tokenizer, 30,522 vocab, max_length 128.
Honest caveat. The RNN/classical numbers (Regime A) and the DistilBERT numbers (Regime B) were measured under different data splits, sequence lengths, and metrics — one uses bias-aware AUC on the large imbalanced set, the other uses plain ROC-AUC on a balanced 20k val set. So their headline numbers are not directly comparable. We do not put them side by side and pick a winner on raw accuracy. Instead we compare behaviour, especially recall on the toxic class.

Takeaway. For moderation, recall on the toxic (minority) class is the number that actually matters. A missed toxic comment (false negative) is the costly error — it reaches users. High accuracy on an 11.5:1 split can hide a model that misses most toxic comments, so we judge models by how much of the toxic class they catch.
STAGE 1 · CLASSICAL & RNN BASELINES

Stage 1 — Classical and RNN models (the LSTM family)

This was the first modelling stage on the English Jigsaw task. The aim was to set a baseline before trying anything heavier. We built a bag-of-words classifier and then a family of recurrent networks, all on the same data.

Honest caveat. These classical and RNN baselines were primarily a teammate's contribution (Debangshu Dey). We use them here as a comparison family. The DistilBERT transformer and the product stack are the author's (Niladri Hazra) track. We do not claim the author trained the LSTMs.

(a) What we built

All RNN models used the same input setup: a Keras tokenizer with a vocabulary of 100,000, sequences padded or cut to a maximum length of 300, and pretrained word embeddings of shape 276,289 × 300. These embeddings are context-free: each word has one fixed 300-d vector, the same vector no matter where the word appears.

  • TF-IDF + Logistic Regression — a bag-of-words classifier (SGD, log-loss, alpha = 1e-5).
  • Single LSTM (128 units, 10 epochs).
  • BiLSTM — two BiLSTM layers of 128 units, global max pooling, dense head.
  • Weighted BiLSTM — the same with class weights to fight imbalance.
  • BiGRU + Attention (64 units, attention).
  • BiGRU-Conv1D + Attention (64 units, attention, plus a Conv1D layer).

(b) Real results

(c) The mathematical reason the RNN approach is limited

The limits below are general theory literature, not specific to our run.

h_t = f(h_{t-1}, x_t)
path length between token i and token j = O(|i − j|) steps
→ a signal from token i to token j passes through |i − j| multiplications
→ repeated products shrink or grow → vanishing / exploding gradients
  • Sequential recurrence. The hidden state is computed step by step. The path between two tokens grows with their distance, so a long-range dependency must survive many matrix multiplications. LSTM gating (Hochreiter & Schmidhuber, 1997) softens this but does not remove it. literature
  • No parallelism over the sequence. Because step t needs step t−1, the network must unroll one token at a time, so training and inference are slow. literature
  • Context-free embeddings. One fixed vector per word. "kill" in "you killed it!" (praise) and "kill" in a threat start from the same vector, so the RNN must separate them from a weak signal. literature
  • Information bottleneck. The whole left context is squeezed into a single fixed-size hidden vector. literature

(d) The drawback we actually saw

These are our measured numbers measured by us.

  • High accuracy hides low toxic recall. On the imbalanced set, TF-IDF+LogReg has a toxic recall of about 0.448 and the Single LSTM about 0.452. They miss more than half of toxic comments while still reading as roughly "94% accurate" on imbalanced data. BiLSTM reaches a toxic recall of about 0.914, but at a much lower validation accuracy (0.8114).
  • Diminishing returns from architecture tweaks. Making the model bidirectional, then weighted, then attention-augmented only moves the Bias-AUC from about 0.89 up to about 0.92. The extra machinery does not break past this band.
Takeaway. The ceiling here is the representation, not the wiring. Context-free word vectors plus a sequential, fixed-size bottleneck cap what these models can learn, and stacking more recurrent layers on top of the same embeddings gives little back. This is what motivates a contextual, attention-based, pretrained transformer.

(e) What it motivates

The next stage replaces context-free vectors with context-dependent ones and replaces the sequential bottleneck with attention, so every token can reach every other token in one step. That is Stage 2: fine-tuning a pretrained transformer (DistilBERT).

STAGE 2 · DISTILBERT TRANSFORMER

Stage 2 — DistilBERT: a fine-tuned transformer

The RNN models in Stage 1 read a sentence one word at a time and kept a single fixed vector per word. That gave two problems: long-range context decays as it passes through the chain, and a word like "killed" gets the same vector whether it is a threat or a sports headline. A transformer fixes both. We did not train one from scratch — we took an existing pretrained model and fine-tuned it.

Why attention beats recurrence

The transformer (Vaswani et al., 2017 literature) replaces recurrence with self-attention. Three properties matter here:

  • Short path length. Self-attention connects every pair of tokens directly, so the path between any two words is O(1), against O(n) for an RNN that must pass information step by step. Long-range context is reached in one hop. literature
  • Contextual, bidirectional embeddings. Each token's vector is computed from the whole sentence, so the same word gets a different representation in a different context. This is what removes the fixed-vector limit behind the "killed it" problem. literature
  • Parallel and pretrained. All positions are processed in parallel (no sequential dependency), and the backbone is pretrained on a large corpus. Fine-tuning then needs only a little task data — this is transfer learning. literature
RNN inter-token path = O(n) → signal decays over distance
self-attention inter-token path = O(1) → direct long-range link

What we actually did

We did not distill anything ourselves. We took the already-distilled distilbert-base-uncased and fine-tuned it. DistilBERT (Sanh et al., 2019 literature) is the result of distilling BERT-base into a smaller student: about 66M parameters, 6 transformer layers, roughly 40% smaller and 60% faster than BERT while keeping about 97% of its performance literature. We fine-tuned it on a balanced 100k subset of Jigsaw (50k toxic + 50k non-toxic, split 80k train / 20k val) measured by us.

The architecture, layer by layer: WordPiece tokenizer (vocab 30,522, max length 128) → embeddings → 6 transformer blocks (each with 12 attention heads and a feed-forward block 768→3072→768) → the first-token [CLS] hidden state (768-d) → pre_classifier Linear(768→768) with ReLU and dropout → classifier Linear(768→2) → softmax giving P(toxic). Training used the HuggingFace Trainer with AdamW, learning rate about 5e-5, batch size 16, on a single GPU.

The drawback that remains

Honest caveat. Four limits stay with this model. (1) It is a compressed model — 66M params, 6 layers — so it has a capacity ceiling. (2) Mild overfitting at 3 epochs: training to 3 epochs lowered training loss (0.6075 → 0.4207) but raised validation loss (0.537 → 0.818) with no accuracy gain, so about 1 epoch was near-optimal for this 100k subset. (3) It is a single model — its errors have an irreducible variance that one model cannot average away. (4) Scope limits: English, uncased, a 128-token cap, and trained only on the balanced subset.

This points to two ways forward. Raise the capacity ceiling by scaling the model up (Stage 3), and reduce single-model variance by combining several models (Stage 4).

STAGE 3 · A BIGGER TRANSFORMER

Stage 3 — Scaling up to a larger transformer

The next idea was to ask: what if we made the model bigger? In an early discussion this was phrased as moving to a "DistilBERT large". We want to be honest about two things up front.

Honest caveat. We did not run any larger-model experiment. There is no measured number on this slide. Everything here is reasoning plus what other people have reported. Treat every claim as literature or proposed next step, never as something we measured.

First, the naming

There is no official "DistilBERT-large". DistilBERT only ships as a base model (~66M params, 6 layers). DistilBERT is itself a compressed version of BERT-base. So the real way to add capacity is to undo the compression and use a full-size encoder instead:

Why a bigger model should help — bias-variance reasoning

A model's expected error can be split into three parts. This is standard theory, not a measurement.

Expected error = bias² + variance + irreducible noise

bias² → how far the model class is from the true function (too simple = high bias)
variance → how much the fit changes with a different training sample
noise → label / data randomness we cannot remove

A larger encoder has more capacity, so it can fit the true function more closely. That lowers bias. This is the reason fine-tuned transformers were the best single models in the Jigsaw competition literature.

What we gain

  • Lower bias — more capacity to fit the true function.
  • Best single-model behaviour, matching the Jigsaw result literature.

What we pay

  • Higher variance / overfitting risk on a small balanced set (ours was 100,000 rows).
  • Much more compute and memory (BERT-large is ~340M vs ~66.96M).
  • Diminishing returns — each size step buys less.

We have a real reason to worry about the variance side. Our 3-epoch DistilBERT run already showed mild overfitting: training loss fell (0.6075 → 0.4207) while validation loss rose (0.537 → 0.818) with no accuracy gain measured by us. A larger model on the same small set would likely overfit sooner, not later.

Honest punchline. A single bigger model raises the ceiling, but it does not remove single-model variance or correlated errors — one model still makes the same kind of mistakes every time. In the Jigsaw competition no top team relied on one model; the best teams averaged several diverse models literature. That is what Stage 4 looks at.
Takeaway. Going bigger (BERT-base 110M or BERT-large ~340M) is the honest way to add capacity, and it would lower bias — but it costs far more compute and does not fix the variance problem. So the more useful next step is not "one bigger model", it is "several diverse models averaged together".
STAGE 4 · ENSEMBLE BY SIMPLE AVERAGING

Stage 4 — Ensemble learning by simple averaging

This is the technique we are bringing in now. The idea is short: train several different models, then average their predicted probabilities. This is called a simple average ensemble — no weights to tune, no extra model on top, just the mean of each model's P(toxic).

Why it works — the maths

The result below is standard ensemble theory, not something we measured. We follow Krogh & Vedelsby (1995). literature

Setup: K models, each with the SAME bias and error variance σ².
The simple average is  f̄ = (1/K) × Σ fi.

Case 1 — independent errors:
  bias( f̄ ) = bias( fi )  (unchanged)
  Var( f̄ ) = σ² / K  → variance shrinks, bias does not grow.

Case 2 — errors with pairwise correlation ρ:
  Var( f̄ ) = ρσ² + (1 − ρ)σ² / K
  As K → ∞,   Var( f̄ ) → ρσ².

⇒ the floor is set by ρ. Adding more copies of one model (high ρ) buys little; the gain comes from LOW correlation, i.e. DIVERSITY.

Ambiguity decomposition (Krogh & Vedelsby):
  ensemble error = (mean individual error) − (mean ambiguity / diversity)
  ambiguity ≥ 0 ⇒ ensemble error ≤ mean individual error.
  (For a convex loss this also follows from Jensen's inequality: loss(mean of predictions) ≤ mean of loss(predictions).)
Takeaway. Averaging cuts variance without adding bias, and the benefit scales with how uncorrelated the models' errors are. So you average diverse architectures — a transformer, a larger transformer, and an RNN — not several copies of the same model.

Evidence — what the Jigsaw competition actually did

The same Jigsaw "Unintended Bias" task we used for the English track was a Kaggle competition, so we can look at what the top teams did. literature

  • Qishen Ha's 8th-place solution was titled "8th Place Solution (4 models simple avg)" — literally four diverse models combined by simple averaging of predicted probabilities. (We have the public title and competition write-ups; we do not have the four exact architectures, so we say "four diverse models" and do not name them.)
  • The competition consensus was that a fine-tuned BERT was the best single model, but every top team ensembled diverse models — BERT-base, BERT-large, GPT-2, and LSTM-based models — by averaging or weighted-averaging (e.g. the 2nd-place "power 3.5 weighted sum"). No top team relied on a single model.
  • To handle the bias metric and the imbalance, teams also used sample weighting (up-weight toxic + identity examples; target weight × log(annotator_count + 2)) and negative down-sampling (drop 50% of negatives after epoch 1).

Multi-sample dropout — a mini-ensemble inside one model

Inoue (2019, arXiv:1905.09788) gives a cheaper, related trick that lives inside a single model. literature

  • Within ONE training iteration, draw k different dropout masks and push the input through each. The duplicated layers share weights, so there are no extra parameters.
  • Average the per-sample losses across the k masks and back-propagate that.
  • Effect: faster convergence and better generalisation at almost no extra cost — an intra-model mini-ensemble. (We describe the mechanism only; we do not quote the paper's exact error-reduction numbers, which we have not verified.)

THE FINAL ENGLISH MODEL · CAPABILITIES & LIMITS

The final model — what it does and where it stops

This is the saved English model: a fine-tuned DistilBERT classifier, served end to end. It is one model behind one API, used by three clients. Below is an honest split of what it can do and what it cannot.

What it can do

Contextual transformer

Six transformer blocks read the whole sentence at once, so the same word is read differently depending on its context — unlike the fixed word vectors used by the RNNs.

Measured accuracy

On the balanced 20k validation set: accuracy 0.8851, F1 (toxic) 0.887, ROC-AUC 0.9515. measured by us

Catches most toxic comments

Toxic recall 0.899 — it misses about one in ten toxic comments, far better than the simple high-accuracy models that miss over half. measured by us

Served end to end

A FastAPI service runs the model, with a fallback chain (real model → LLM via gateway → keyword heuristic) so a live demo never hard-crashes.

One contract, three clients

A React website, a Chrome extension (X / YouTube / Instagram), and an Expo mobile shell all speak the same API contract.

Explanations + a tunable threshold

Per-category scores and word-level explanations (occlusion), plus a decision threshold a moderator can move to trade precision against recall.

Where it stops

  • English-only and uncased. The tokenizer lowercases input, so it loses signal from SHOUTING in all caps. measured by us
  • Short inputs only. Hard cap of 128 tokens; longer comments are truncated. measured by us
  • Trained on a subset, not the full corpus. A balanced down-sample of 100,000 comments (50k per class), not all 1,804,871. measured by us
  • Binary head only. It outputs toxic / non-toxic; it does not name the toxicity type from this head.
  • Mild overfitting past one epoch. Three epochs lowered training loss but raised validation loss (0.537 → 0.818) with no accuracy gain, so ~1 epoch was near-optimal for this subset. measured by us
  • Identity bias not yet mitigated. The dataset's identity columns make bias measurable, but we have not measured or corrected it here.
  • It is a single model. One model carries single-model variance and correlated errors — exactly what the averaging step (Stage 4) is meant to cut. proposed next step
Takeaway. A solid, honest single classifier — 0.8851 accuracy, 0.887 F1, 0.9515 ROC-AUC, ~0.90 toxic recall — that works end to end across three clients. Its main open weaknesses are English-only / uncased input, unmitigated identity bias, and being a single model.
Honest caveat. These numbers are for the English DistilBERT track only. They are not a baseline for the Hindi RAVEN-X work, which is a different language, task, and label scheme.
OUR ORIGINAL METHOD · LOW-RESOURCE HINDI

RAVEN-X — our original contribution (Hindi, cross-script rationale transfer)

Why we re-scoped the project

Our supervisor, Dr. Arpita Dutta, is second author of the survey "A Survey on Automatic Online Hate Speech Detection in Low-Resource Languages" (arXiv:2411.19017). That survey points to low-resource and code-mixed Hindi-English as the open gap. Building another English Jigsaw model is a reproduction, not a contribution. So she asked us to propose our own method in low-resource Hindi instead. RAVEN-X is that method.

Data truth — what we actually measured on disk

We checked the HASOC-2019 Hindi file ourselves (4,665 rows). It is native-script Hindi, not romanized Hinglish: measured by us 82.5% of script characters are Devanagari; 74.9% of posts are Devanagari-dominant and only 7.3% are Latin-dominant. This matters for the method: a Devanagari slur and its English equivalent share zero subword tokens. So any transfer from English to Hindi cannot ride on shared spelling. It has to pass through MuRIL's shared meaning space, purely as representation.

The official gold test set is blind, so we cannot use it. We froze a stratified split with seed=42 and report on it: train 3,265 / val 699 / test 701.

The method

One shared MuRIL-base encoder (12 layers, 768-d, ~236M params) feeds two heads:

CLASSIFY head

Toxic / not toxic. Supervised on Hindi HASOC and English data together.

RATIONALE head

Which words are toxic. 768→256→1 per word. Supervised only on English HateXplain — never on Hindi.

The two heads are tied together by a per-head-masked multi-task loss: each loss term applies only where its label exists, so we never train on a missing label. On top of that we add a label-free faithfulness self-objective on Hindi — comprehensiveness and sufficiency, measured by masking words at the attention level and re-running the full encoder. Each batch of 16 is mixed: 8 HASOC-Hindi + 8 HateXplain-English. AdamW, discriminative learning rates (2e-5 encoder / 1e-4 heads), max_len 128, fp16, on a T4 GPU.

Why this is novel — and the honest negative-result framing

The novelty is the conjunction of three things at once: cross-script (English → Devanagari Hindi), at the rationale level (word-by-word, not just a label), with zero target-language rationale labels. We test whether explanation faithfulness survives the script boundary with a label-free deletion test we built, not an assumption. If the answer turns out to be no — that transfer does not survive crossing into Devanagari — that is still a rigorous negative result the field does not currently have, and reporting it honestly is itself a contribution.

Takeaway. RAVEN-X is one MuRIL encoder with two heads and a masked multi-task loss. On our frozen split it reached macro-F1 0.842 on validation, +5.5 points over the TF-IDF baseline (0.787), and we directly measured the accuracy-versus-explainability trade-off the design predicted.
Honest caveat. This is a fast single-seed run; MuRIL validation was capped at 400 examples by the eval loop and the clean MuRIL test number is still pending. The headline result — whether faithful explanations transfer across script into Devanagari — is the pending Week-4 measurement, not yet done. And the English DistilBERT 0.885 is not a baseline here: it is a different language, task, label scheme, and class balance, so comparing the two would be a category error. It served only as motivation.
WHAT WE NEED NEXT · CONCRETE STEPS

What we need next

Here is the honest state of the work and the small set of things left to finish. None of the numbers below are claimed as results yet. Each item is a planned step, with the real single-model numbers we already have as the starting point.

English track

  • Train and average the ensemble. proposed next step Actually train three diverse models — our fine-tuned DistilBERT, a larger transformer (e.g. BERT-base), and an RNN-family model — and combine them by simple averaging of predicted probabilities. Then measure the gain. Our starting point is the real DistilBERT 3-epoch number: accuracy 0.8851, F1 (toxic) 0.887, ROC-AUC 0.9515. The expected benefit comes from low error correlation across diverse architectures, following the Qishen Ha 8th-place "4 models simple avg" result and the standard variance-reduction theory; we will report only the measured ensemble score, not a guessed one.
  • Add multi-sample dropout. proposed next step Within one training step, draw k dropout masks and average the per-sample losses (Inoue, 2019). It is an intra-model mini-ensemble at almost no extra cost. We will measure whether it improves convergence and validation loss on our split.
  • Add bias-aware sample weighting. proposed next step Up-weight toxic and identity examples (target weight scaled by log of annotator count), as the top Jigsaw teams did, and report the Jigsaw bias-aware AUC alongside accuracy.
  • Report on one common split. proposed next step Right now the RNN family (large imbalanced split, bias-aware AUC) and DistilBERT (balanced 20k val) are not directly comparable. We will re-evaluate the models on one shared split so the numbers can sit in one table.

RAVEN-X track

  • Full multi-seed run. proposed next step The current MuRIL number (val macro-F1 0.842, epoch 2) is a single fast seed-42 run with the val loop capped at 400 examples. We will run 3–5 seeds and report mean ± std on the full val set.
  • Script-stratified faithfulness on Devanagari. proposed next step This is the headline that is not yet measured. We will measure comprehensiveness and sufficiency of the rationales on the native Devanagari posts (82.5% of script characters are Devanagari), since the rationale head is supervised only on English. That tests whether explanation transfers across scripts with zero shared subwords.
  • Clean held-out test number. proposed next step Report MuRIL on the frozen test split (701 rows). The TF-IDF baseline is macro-F1 0.813 test; the MuRIL test number is still pending.
  • Geometry probe. proposed next step Check, in MuRIL's shared embedding space, whether a Devanagari slur sits near its English equivalent — evidence for why cross-script transfer can work at all.

Resources we need

  • A small amount of GPU time. proposed next step A free T4 is enough for the RAVEN-X multi-seed and faithfulness runs (the first run was on a Colab T4). The English ensemble plus the larger transformer (BERT-base) needs a bit more compute than a single T4.
  • Continued access to the gated Hindi datasets. proposed next step We need ongoing access to HASOC-2019 Hindi (4,665 rows) and HateXplain so we can finish the multi-seed and cross-script evaluation.
Takeaway. The remaining work is finishing and measuring, not redesigning. For English: train and average the ensemble and report a gain over our real DistilBERT numbers. For RAVEN-X: multi-seed runs, the Devanagari faithfulness headline, a clean test number, and the geometry probe. The cost is modest — mostly a little GPU time and continued dataset access.
